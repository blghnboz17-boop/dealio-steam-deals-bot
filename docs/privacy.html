Privacy Policy

Effective date: August 22, 2026. Last updated: August 23, 2026.

This Privacy Policy explains how personal data and related information are processed when you use the Dealio Discord bot and visit its legal website (together, the "Service"). Bilgehan Boz, located in Canakkale, Turkey, is the operator and data controller for processing carried out by Dealio.

1. Scope and data sources

We receive information directly from you through Discord slash commands, from Discord as the interaction and messaging platform, and from Valve services when Dealio checks the public Steam wishlist you identify. Discord, Valve, and the website host also process information independently under their own privacy policies.

2. Information submitted through Discord

When you interact with Dealio, the bot receives your Discord user ID and slash-command data. Depending on the command, this may include a SteamID64, Steam profile link, or Steam vanity name you enter, your selected notification language, the country configured for your Steam Store account, a manual-check request, or a deletion confirmation. The selected Store country is not inferred from your Discord location. Discord also supplies technical interaction metadata such as the interaction and application identifiers and the server context in which the command was used.

Dealio uses the Discord Guilds gateway intent. It does not request privileged Message Content, Guild Members, or Presence intents and does not read ordinary user conversations. Discord still processes slash-command options, ephemeral command replies, and direct messages generated by the bot under Discord's own practices.

3. Information stored in the active database

Dealio may store the following in its active SQLite database:

  • your Discord user ID;
  • your current configured public SteamID64 and Steam IDs retained in records associated with earlier configuration versions;
  • your notification language, selected Steam Store country code, enabled status, global and game-specific minimum discount settings, internal configuration identifiers and version, and creation or update timestamps;
  • check start and completion times, status, next scheduled time, and limited error codes;
  • the latest observed state for each wishlist app and configuration version, including app ID, Store country, sale state, regional price, currency, discount, sale-episode identifiers, observation reliability, and observation times; and
  • sale-notification records, including the game name, relevant price information, delivery status, failure or retry count, attempt and retry times, and the latest delivery error.

The database is designed to maintain the state needed to detect sale transitions and avoid duplicate alerts. Steam profile links, vanity names, their query strings or fragments, and the Steam Web API key are not intentionally stored in SQLite. It is not intended to maintain a complete history of every wishlist observation or every price ever returned by Steam.

4. Information processed from Steam

During setup, Dealio parses numeric SteamID64 and /profiles/ links locally. If you submit a vanity name or /id/ link, Dealio sends the validated vanity name to Valve's official ResolveVanityURL service and receives a canonical SteamID64. It then sends only that canonical SteamID64 to Valve to verify that the wishlist is publicly accessible. Query strings and fragments from submitted profile links are discarded and user-provided URLs are not fetched. During checks, Dealio sends the canonical SteamID64 to Steam's wishlist service and sends wishlist app IDs, the selected two-letter Store country code, and the selected response-text language to Steam's store-details service. Valve may also receive ordinary network data, such as the requesting IP address, and processes that information under its own policies.

Steam may return wishlist app IDs, priority, date-added values, game names, and regional price information. Wishlist priority and date-added values are handled transiently and are not intentionally stored in Dealio's database. Dealio accepts the currency returned by Steam for the selected Store country and does not perform currency conversion. Dealio does not verify that the selected country matches the Steam account's actual Store setting and does not send your Discord user ID to Steam.

5. Operational logs

Dealio creates local standard-output, error, lifecycle, and health files to operate and troubleshoot the bot. Routine entries are generally timestamps, process state, aggregate user or wishlist counts, check results, and notification totals. Unexpected errors may include additional technical metadata supplied by Discord, Steam, the runtime, or a network response.

The application does not intentionally write raw Steam profile setup input, vanity names, Steam or Discord passwords, the Steam Web API key, or the bot token to these logs. Operational logs are retained until they are overwritten or manually removed and are not currently subject to an automatic retention schedule. The /delete-data command does not search or delete these files.

6. Purposes of processing

We process this information to:

  • create and maintain your Dealio configuration;
  • validate and check the public Steam wishlist you select;
  • establish a baseline and detect later transitions to an on-sale state;
  • send, retry, and account for requested Discord notifications;
  • prevent duplicate notifications for the same sale episode;
  • respond to status, manual-check, and deletion commands;
  • diagnose failures, secure the Service, prevent abuse, and maintain availability; and
  • meet applicable legal obligations and establish, exercise, or defend legal claims.

11. Retention and deletion

Records in the active SQLite database are retained while your configuration remains active and until you run /delete-data confirm:true or the operator deletes them. The current application does not automatically delete database records after a fixed period. Old configuration-version records, sent or failed notification records, and the latest observed wishlist states therefore remain until account-level deletion or operator maintenance.

Running /delete-data confirm:true deletes your configuration from the active database and uses database relationships to remove the associated discount settings, check state, wishlist state, sale episodes, and notification history. SQLite secure deletion is enabled for deleted content in the active database. This feature does not guarantee erasure from storage-device history, filesystem snapshots, Discord or Valve systems, operational logs, or external backups.

The application does not currently create or manage a separate backup system. If host-level or manually created backups exist, the deletion command does not modify them. Discord messages, interaction records, Valve request records, and GitHub request logs are retained by those providers according to their own practices.

12. Security

We use reasonable technical and organizational measures appropriate to the current scale of the Service, including environment-based secret handling, fixed HTTPS Steam API endpoints, strict Steam profile input validation, request timeouts, limited Discord gateway intents, access controls provided by the host operating system, and SQLite secure deletion. However, no storage or transmission system is completely secure, and we cannot guarantee absolute security.
